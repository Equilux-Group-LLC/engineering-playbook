# Review rubric: iOS profile

`ai-review.yml` appends this file to the reviewer's prompt when a caller passes `profile: ios`. It adds to the
repository's rules file (`AGENTS.md`, which in `ios-app-template` carries the same ban list and rubric); where
the two disagree, the stricter rule wins. Source: `ios-app-template`'s `AGENTS.md` and the iOS profile's rubric
additions (`../ios.md`, section 7).

## Ban list (each hit is a BLOCKER)

SwiftLint enforces these in `verify`, but a reviewer still flags each one it sees:

`ObservableObject`, `@Published`, `@StateObject`, `@ObservedObject`, `@EnvironmentObject`, `NavigationView`,
`NavigationLink(isActive:)`, `.foregroundColor`, `.cornerRadius`, completion-handler networking,
`DispatchQueue.main.async` in SwiftUI, `@unchecked Sendable`, `print`.

Also banned: hard-coded colors or fonts in views (use theme roles), secrets or tokens in `UserDefaults`, the
bundle or an xcconfig, force-unwrapped decoding, icon-only buttons without an accessibility label, and Worker
routes without `requireSession`.

## BLOCKER (do not merge)

- Anything on the ban list.
- A secret, token or credential in the repo, bundle, xcconfig, `UserDefaults`, logs or a fixture. Session
  tokens belong in `KeychainStore`.
- Real PII or PHI anywhere: code, fixtures, seeds, docs, commits. Fixtures use `example.invalid` addresses.
- A Worker route not on the `api` router behind `requireSession`, a query not scoped to `c.var.userId`, or a
  table with a `user_id` column missing from `userOwnedTables` — anything that lets user A read or change user
  B's data.
- A missing or weakened test for changed behavior; a skipped, deleted or loosened test; a re-recorded snapshot
  without a note in the PR saying why.
- **An edit to a `*.pbxproj`.** The project is generated by XcodeGen: the change belongs in `project.yml`,
  followed by `scripts/generate`. `*.xcodeproj` is git-ignored, so a tracked `.pbxproj` in the diff is itself
  the defect.
- A new dependency (Swift package, npm package, GitHub Action, MCP server) that was not approved, or one not
  pinned to an exact version with its lockfile or `Package.resolved` committed.
- **Health data in iCloud or CloudKit** (including `NSUbiquitousKeyValueStore` and CloudKit-backed
  containers) without an ADR in `docs/decisions/` citing App Review Guideline 5.1.3(ii).
- A missing usage string for a permission, or a permission requested at launch instead of at the moment of use.
- `NSAllowsArbitraryLoads`, or a force-unwrapped decode of network data.
- Logging through anything but `AppLog.logger(category:)`, or user-related values marked `.public`.
- A change that breaks `scripts/verify`.

## SHOULD-FIX

- Missing `#Preview`; missing `accessibilityIdentifier` on an interactive element.
- Unclear names; copy built by concatenating sentences.
- A model doing work a service should do; a new service with no Fake; a model file over 300 lines.
- A non-obvious decision without a doc or ADR.

## Name what you could not verify

In the top-level comment, list what you could not check from the repository alone, specifically: anything that
needs a simulator or device (UI behavior, VoiceOver, Dynamic Type), signing and entitlements as provisioned in
App Store Connect, Worker secrets and D1 state in Cloudflare, and anything a missing tool stopped you from
checking, naming the tool. Read the `verify` result with `gh pr checks`; don't infer it.
